# 架构约定

项目采用模块化单体：部署仍是一个 Web 服务和一个文档 Worker，但代码按 HTTP、领域服务和前端功能划分。

## 后端

- `server.mjs` 是组合根，只负责创建依赖、应用公共安全策略、依次调用路由和启动服务。
- `server/routes/` 按业务域处理 HTTP 路由。路由负责鉴权、解析输入、调用服务并形成响应，不直接实现领域规则。
- 当前已迁移的路由域包括公开状态与模板列表（`public.mjs`）、模板详情与简历草稿（`resumes.mjs`）、账户会话与个人设置（`account.mjs`）。
- `server/http.mjs` 提供无业务含义的 HTTP 与静态文件公共能力。
- `server/*.mjs` 与 `server/ai/*.mjs` 承载服务、仓储和领域规则，避免依赖具体路由。

新增接口时应优先加入对应的 `server/routes/*.mjs`，不要继续向 `server.mjs` 添加大段业务分支。现有路由按测试覆盖逐域迁移。

## 前端

- `public/app.mjs` 暂时是组合根，保留页面启动、共享状态装配和事件分发。
- `public/api-client.mjs` 统一解释 API 成功、错误和未登录响应。
- `public/admin-api.mjs` 集中管理端配置与认证密钥相关的 HTTP 协议，页面模块只处理表单和渲染。
- `public/resume-api.mjs` 统一模板目录、草稿 CRUD 和版本记录协议；编辑器只维护本地状态与交互。
- 独立、无业务状态的界面能力放在单独模块，例如 `public/theme.mjs`。
- 后续功能按 `public/features/<domain>/` 迁移，模块通过明确参数或回调交换状态，避免读取其他功能的模块级变量。

## 迁移原则

1. 一次迁移一个业务域，保持 URL、JSON 协议和 DOM 标记不变。
2. 先搬迁并保持现有测试全绿，再做内部设计优化。
3. 不为了目录整齐引入微服务、前后端分仓或框架重写。
4. 跨域共享能力必须足够通用，业务规则留在所属领域。
